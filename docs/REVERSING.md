# Reverse-engineering reference

Build 19145763. Function ids (`f@N`) are **hlboot.dat only**; `hlbootdx.dat` numbers differ, so resolve by name (`mod find`).

## Engine

- Shiro Games engine: Haxe → **HashLink bytecode** (`hlboot.dat`; `hlbootdx.dat` = DirectX build). `D4X.exe` is only a launcher. Names and source file/line survive; `.hx` sources are not shipped.
- `crashlink` (pip, in `.venv`) parses/serializes both boot files byte-identically and decompiles to pseudo-Haxe. The decompiler is imperfect (duplicated branches, `var17[1]` for `[i]`); confirm with `--asm`. `$AIMilitary.getSiegeableVillages` hangs the decompiler: use `--asm`.
- Resources: `res.compressed.pak` (Heaps PAK, `tools/pak.py`), then `res.compressed1.pak`, `2`, … up to the first missing number; later files replace same-path files, so two mods replacing `data.cdb` conflict.
- `data.cdb` = CastleDB JSON (~90 sheets). Code reaches rows by id and by index: never reorder or delete rows. Key sheets: `constant` (1309 rows, 415 `AI_*`, `values[]` = per difficulty Easy/Medium/Hard/Insane, or a [min,max] pair for ranges), `unit`, `ability` (`props.ai`), `structure` (`startUnits`), `faction` (`startResources`), `gameMode`, `parameter` (`constOverrides`), `militaryGauge` (`props.onSuccess/onFailure` blocks), `action`, `need`.
- Constants are read via `Const.valueCache[i]` / `fValuesCache[i]` / `iValuesCache[i]` (row index).

## Military decision flow

- **Gauges:** `AIMilitary.regularUpdate` → gauges ≥ `valueCache[1116]` (100) and not paused → `tryGauge(random valid gauge)` → `tryAnnexation/tryPillage/...` → `tryAction(kind, args)` → `tryArmyAction(k, structure, data)` → `onActionEnd(gaugeKind, EReason, data)`: runs `militaryGauge.props.onSuccess/onFailure` blocks (not for `Skip`), un-pauses the gauge, then `impactNeeds` (Success ×`[1117]`, `NotImplemented`/`Dismiss` no change, `ArmyNotStrongEnough` also requests recruitment, else ×`[1118]`). Only Raze has `onFailure` blocks. `getMilitaryGaugeKindFromSiegeActionKind(k)` maps action → gauge.
- **Orders:** `tryArmyAction` → `HAI.getDefaultUnitActionQueryArgs` → `pickUnits` → `AIOrders.addOrder(type, prio, armies, target, action, siegeAction, mandatoryMissions, optionalMissions, data, onComplete)`. Phases: 0 Paused, 1 Waiting, 2 Preparation (paths, possibly Shuttle steps), 3 Regroup, 4 Engage, 5 Action, 6 Retreat. End: `AIOrder.stop(reason)` → `removeOrder`. `AIOrderType`: Basic, Military, Defense(e), Protect(e), Resupply(f,f), Discovery(e), Patrol(e), Investigate(e), SendAssassin(e). `AIOrderTargetType`: Entity, Unit, Army, Ornithopter, Harvester, Structure, Group. `AIOrder.getTarget()` = the targetType enum parameter. `ActionEndReason`: Success, Fail, Cancel, Override.
- **pickUnits** args: `consideredUnits, enemyStructure, enemyUnits, targetFaction, requiredPowerBalance (1), allIn, ignoreMelee, ignoreOtherFactionArmies, simulatePendingArmies, allyStructure, allowShips/Frigates`. Candidates sorted by distance, added one by one, `HPowerScore.compute` (`balance = my / enemy`), returns once balance ≥ required; can count units in recruitment. `tryArmyAction`: no idle units → simulate all armies (`aiOwner.armies`, harvesters included) → empty `ArmyNotStrongEnough` / else `NoAvailableArmy`; idle units but an empty real pick → same simulation → empty `ArmyNotStrongEnough` (recruits) / else `NotEnoughArmies` (waits). `Structure.siege` is a SiegeComponent on every village: an active siege = `besiegingFaction` or `getOccupierFaction` non-null.
- **getUnits** (siege idle query): minLife 0.9 **only if `hasSafeRegen`** (otherwise any life: a Harkonnen army at 25% counted as idle for Annex / Pillage / Defense; `pick-life`), minSupply 0.9, excludes armies in orders with priority ≥ the action's `siegeAction.props.aiPrio` (Annex 3, Pillage 1, Liberate 1, Raze 4). Its busy closure (f40983; dx f40930) reads `(target as Structure).siege.isUnderSiege` for Military orders in phase 5: null for non-structure targets (patched, see `busy-siege`). So an Annex (3) takes armies from a gathering Liberate / Pillage (1), and `AIOrder.removeUnit` before Action cancels that whole order. **keep-order** (pick-life wrapper, `tryArmyAction` sites only): an army in a Military order (any target, our hunts too) with ≥ 2 units and phase < 5 is dropped from the result, log `keepord` (f, a, sa, n, ph; per army per PICK_LOG_T). Defense (`checkStructures`) is not filtered: it may still take them.
- **checkStructures:** own structures only; skips those with an order; `siege.isUnderAttack()` → units within 80 → `pickUnits(allyStructure, enemyUnits, getDefenseRandomPowerBalance, ...)` → `addOrder(Defense(s), prio 10 main base / 5)`.
- **getSiegeableVillages** (f@8416): candidate filters (allowNeutral/allowEnemy/unreconned/sietch/mainBase/orders). Wind filter: `considerWater && compareGoals(water) < 0 && structures > 1` → drop zones with `windForce < valueCache[1185]`. `tryAnnexation` sets `allowEnemy=false` below the required aggressiveness. Per candidate: skip neutral unless allowNeutral, owned unless allowEnemy, `capture.isCapturing`, sanctuaries, attribute 1442; an owned village is skipped when `faction.aiController.diplomacy.getTargetStatus(owner)` (f@8464 = `_factionData.get(f).desiredStatus`) is 0, and when at peace with it unless `DiplomacyManager.canDeclareWar` (cached per pair); then supply range (`isInSupplyRange` f@8409: zone distance ≤ `maxSupplyDistZones`), mainBasesOnly, `getAvailableOccupationActions` contains k, devastation, `canFightWith`, cost. `Diplomacy.dailyUpdate` (f@8466): desiredStatus = 0 forcePeace / 2 forceTotalWar / else the sign of `HScoring.diplomaticTarget` (> 0 → 1, < 0 → 0). `AIMilitary.updateAggressiveness` (f@8381): Σ over players of in-range zones × `fValuesCache[1142]` × (100 − diplomacy index) + round((own − weighted avg `totalArmyPowerScores`) / `valueCache[1139]` 5000) × `[1140]` + `[1138]`, clamped ±`[1141]`, × dt / day; `getActionRequiredAggressiveness` = bounds `[1119]` (0-100) × gauge requirement (0.5 for every gauge). `HScoring.structures` (f@32467): neural-grid weighted features (`HAI.scoring_ent_Structure`) with `HScoring.factions` owner scores.
- **getEnemyCombatStats(structure, units, ignoreOtherFactionArmies)** (callers `pickUnits`, `getOrderPowerBalance`): `structureCombatStats(target)` + owner main base if within its `attackRange` + **owner's** armies weighted by zone distance (`fValuesCache[1067]`/`[1068]`). No third-party armies, no neighbour villages' turrets. `pickUnits` / `getOrderPowerBalance` add `structureCombatStats(allyStructure)` to our side.
- **Combat stats:** `$HCombatStats.structureCombatStats(s)` = [mainBaseCombatStats if main base, siegeCombatStats (militia), buildingCombatStats(b) for each building with power > 0]. Building / main base stats have health 0 (MissileBattery power 40, AOE; main base power 80, AOE; both range 80 in data). `HPowerScore.singlePowerScore(stat)` = offensivePotential × health (0 for turrets); a report's powerScore = Σ offensivePotential × Σ HP × count^`valueCache[1115]`, so turrets add offense only (a lone turret scores 0). `offensivePotential` = (power − enemy armor × penetration) × attackSpeed × damageModifier × aoeFactor × externalFactor.
- **Order cancels:** `checkOrders` cancels when `getTarget().removed`. `checkOrderTerminations` → closure f40838: Group target removed → `stop(null)`; next path step `Shuttle` and `checkUseAbilityOn("Shuttle")` = Invalid(2)/BlockedBy(8) → Cancel; all units dead → Cancel; Military ArmySiege/ArmyFight on a Structure: peace with owner, `!canBeAttacked` or siege lost → Cancel (no Group case). Siege lost = `isUnderSiege` with an occupier of another faction, or no occupier and no besieger of ours (closure f40840: besieger owner ≠ us; an empty list counts): in Action (where `removeUnits` no longer cancels) the death of our only besieger cancels the whole order while the rest is still walking in (Atreides' fast A_Ship at the Pel-fir renegade base, 9 armies, src `<none>`). `addOrder`'s onComplete closure f40799: on Success cancels other phase<5 orders sharing units. `AIOrders.onEvent`: `OnNewTreaty` (Breakable, flag bit 4) cancels orders targeting either party; `OnCompleteSiegeAction` → Success. `checkEngageOrder`'s ArmyFight case calls `entityGroup.getEntities()` unconditionally.

## Decision logging (tools/inject.py, patch `ai-log`)

- **Technique:** new functions are appended (`FB` builder); existing `Call*` ops get their `fun` swapped to a same-signature wrapper, or an `InstanceClosure` op its function. No op insertion, so no jump fixups. `aimod_log(obj)` writes `AIMOD {…}` to `game.log`; `aimod_ent(x)` = `{k kind, o owner, p placeName, x, y}`.
- **Events:** pick (pickUnits), pw (compute inside pickUnits), order (addOrder ×16), end (removeOrder), phase (changePhase/nextPhase), fightb/fpw (getOrderPowerBalance: live my/enemy power), mark (L key / `info`), snap (daily), fight (initFight), micro (changeArmyMicro), stop (AIOrder.stop, one wrapper per caller → `src`; `<none>` = an unnamed closure), call (generic traces from `testbed/ailog.json`), aw, hunt, heal, retreat, space. Every event has `g` (game seconds) and `t` (app seconds). Field lists: aireport.py docstring.
- `end.n` = order army entries, not deaths; use fpw for losses. The game truncates long arrays without a closing `]`; parsers must tolerate it.
- **Generic tracer:** `testbed/ailog.json` `trace` / `trace_per_caller`. Arguments described by static type. Virtual/closure-only functions are untraceable. Keep per-tick functions out; `mod log` flags traces above 30/game-minute.
- **Safety rules for injected code:** never throw into game code: wrap in `Trap` (`FB.try_`/`end_try`), keep the original call outside the trap, read fields with `$Reflect.field` (a `DynGet` of a missing field throws), `ToDyn` only for primitives (pointers take `Mov`; `ToDyn` on a pointer boxes it). Check `mod log`'s `HEALTH` line after every run.
- **Builder notes:** no float constants (use `Int` + `ToSFloat`, `_ratio`); backward jumps need a `Label` op; labels must be unique per function (`_uid`); `aware.B` wraps typed Call/Field/SafeCast.
